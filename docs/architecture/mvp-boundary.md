# MVP boundary (V1 desktop-local)

Locked against *System Architecture and Implementation Roadmap V1.1* (§4.3, §5, §8, §12).
Profile **A — Desktop Local** is the V1 product. This document is the Milestone 0 MVP boundary.

## In V1

- One-owner Tauri 2 desktop on Windows and macOS (ARCH-02).
- Local SQLite in WAL mode as operational system of record on the active computer (ARCH-01, ADR-0003).
- Typed `FinanceClient` over restricted Tauri IPC (`LocalTauriFinanceClient`). Screens never embed SQL (ADR-0006).
- Bounded components: Platform (config, audit, approvals, exceptions, health, snapshot/restore), Registries, Capture (evidence, import staging), Financial ledger, Market/dividend, Planning, Reporting.
- Immutable snapshot lineage and controlled device handoff (ARCH-05, ADR-0007).
- Fixed-scale money and exact comparison unless a documented tolerance applies (ADR-0004).
- Golden Business Outcome Harness as a required release-control component (ADR-0013). Scenario **behaviors** G-MAGI-01 through G-MAGI-10 are locked now.

## Forbidden

- Live synchronization of SQLite files.
- Silent merge of divergent snapshot branches.
- Concurrent offline editing (Profile E) without a separately approved design.
- Autonomous trades or money movement (ARCH-09).
- UI, import, connector, or AI adapters posting authoritative facts while bypassing validation/approval (AC-ARCH-12).
- React executing arbitrary SQL.
- Binary floating-point for authoritative money, price, quantity, or rates.
- Auto-approving or regenerating golden expected values by the code under test or an AI process (ADR-0013).
